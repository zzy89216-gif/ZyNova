# PCL-FE 液态玻璃（移植参考）

> 来源：`PCLPro/Modules/Base/ModGlass.vb`（719 行）与 `Pages/PageSetup/Settings.vb`。
> 用途：27.10.2「玻璃地基」。
> **结论先行：只搬视觉配方，不搬实现方式。** PCL-FE 的做法在 WPF 上就已经很卡，
> 照搬到 Android 会更糟（详见第 4 节）。

## 1. 参数（PCL-FE 默认值）

| 参数 | 设置键 | 默认 | 范围 |
|---|---|---|---|
| 模糊半径 | `UiUiBlur` | 18 | 0–60 |
| 卡片圆角 | `UiGlassCorner` | 16 | 0–28 |
| 卡片不透明度 | `UiGlassCardOpacity` | 0 | 0–100 |

`UiGlassCardOpacity = 0` 表示**不加白色底**，只保留模糊 + 描边。

## 2. 视觉配方

**卡片白色渐变**（`GlassCardTint`，按 0–100 缩放）：

| 位置 | 颜色（ARGB） |
|---|---|
| 0 | 22,255,255,255 |
| 0.16 | 18,255,255,255 |
| 0.56 | 26,253,254,255 |
| 1 | 34,251,252,255 |

**弹窗底**（`GlassDialogTint`）：`150,255,255,255` → `120,246,250,255`，方向 (0,0)→(0.3,1)。

**描边**：

- 弹窗边：`76,255,255,255`（1px）；
- 卡片边：`52,255,255,255`（1px）。

**背景快照**：整窗渲染成位图后模糊，像素上限 `4,200,000`，超过则按比例降采样。

## 3. 实现方式（WPF）

1. `SnapshotVisual()`：用 `VisualBrush` + `RenderTargetBitmap` 把整个窗口/背景层画进 CPU 位图；
2. `Blur()`：**CPU 三遍盒式模糊**，4 通道 × 3 遍 × 横纵 = 24 次全图扫描；
3. `_FlushTimer` 90ms 防抖；`_WatchTimer` 每 300ms 轮询壁纸签名；
4. `SizeChanged` 也会触发重建。

## 4. 为什么不能照搬（性能结论）

- 快照是**整窗软件光栅化，且在 UI 线程同步执行**；
- 1080p 下 24 遍像素扫描约 5000 万次运算，单次重建实测 200–500ms；
- 拖动/缩放/切页时会反复排队重建 → 掉帧、不跟手；
- 每个玻璃面板各自持有快照，层数越多越慢。

> 这些结论已经反馈给上游；ZyNova 的 27.10.2 不采用这套实现。

## 5. ZyNova 的做法

1. **背景只模糊一次**：`Background()` 里对整张壁纸做一次模糊（背景模式），卡片不再各自 `hazeBlur`；
2. **卡片只用渐变 + 描边**：`Modifier.codexGlass()`（`ui/components/CodexGlass.kt`），
   深色主题白色 alpha 0.08→0.036、1px 白边；浅色主题用黑色低透明度；
3. **圆角**：面板 28dp、按钮 20dp；
4. **模糊上限**：半径 ≤ 24，低端机自动降到 12 或关闭；
5. **零常驻动画**：不再有流动高光/明暗脉动；
6. 拖动/滚动期间不做任何背景重建。

## 6. 与 27.10.1 现状的差距

- 27.10.1 仍保留旧的 `glass()` + `GlassLevel` 动态高光；
- `BackgroundBlur.Foreground` 模式下每张卡片仍会实时 haze；
- 27.10.2 要做的就是把这两处收敛成第 5 节的单层方案。
